## 1. 구현 내용

### staff — "강사 계정" 메뉴 추가
| 화면 | 내용 |
| :--- | :--- |
| `/staff/instructors` | 강사 목록 + 계정 상태 배지(계정 없음 / 초대 대기 / 가입 완료) |
| `/staff/instructors/new` | **신규 강사 등록** 폼 — 성명, 이메일만 |

초대 시 한 트랜잭션처럼 처리(중간 실패 시 롤백):
1. `inviteUserByEmail(email, { data:{name}, redirectTo })` → auth user 생성 + 초대 메일 발송
2. `instructors` row 생성 (성명·이메일만, 나머지 NULL)
3. `app_accounts` row 생성 (`id`=auth user id, `role='instructor'`, `instructor_id`=2번 row, `display_name`=성명)
- 2·3 실패 시 앞서 만든 auth user / instructors row 삭제

중복: `instructors.email` 사전 확인 + GoTrue "already registered" 에러 → "이미 등록되었거나 초대된 이메일입니다."

### 초대 링크 → 비밀번호 설정
- `/auth/confirm` (라우트 핸들러): `token_hash` 를 서버에서 `verifyOtp` → 세션 쿠키 세팅 → `/auth/set-password` 로 리다이렉트
- `/auth/set-password` (클라이언트): 세션 확인(쿠키 / URL 해시 / `?code` 모두 처리) → 비밀번호 입력 → `updateUser({password})` → `/` 이동 → 역할(instructor) 분기로 #003 프로필 진입
- 두 경로 모두 proxy 의 public 경로(`/auth/*`)

### service_role
- `src/lib/supabase/admin.ts` — `SUPABASE_SERVICE_ROLE_KEY`(서버 전용, `.env.local`) 로 admin 클라이언트. Auth 관리자 API + RLS 우회 쓰기에만 사용.

## 3. 메일 발송 관련 (SMTP)

- `inviteUserByEmail` 은 성공(auth user 생성 + 발송 시도). 실제 메일함 수신 확인은 SMTP 설정 상태에 따름 (본 작업 범위 밖).
- GoTrue 는 이메일 형식/도메인을 검증함 — `@hew.test` 등 예약 TLD 는 거부. 실제 강사 이메일(gmail 등)은 정상.
- **SMTP 설정 후 권장**: 초대 메일 템플릿 링크를
  `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=invite&next=/auth/set-password`
  로 바꾸면 `/auth/confirm` 서버 검증 경로를 그대로 탄다. (기본 템플릿의 implicit 해시 방식도 `/auth/set-password` 가 처리하도록 구현돼 있음)
