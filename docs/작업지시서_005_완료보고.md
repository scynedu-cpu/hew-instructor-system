## 1. 구현 내용

### 1-1. 마이그레이션 `20260909080000_calendar_edit.sql` (RPC 3종, 모두 SECURITY INVOKER)

| 함수 | 역할 |
| :--- | :--- |
| `instructor_time_conflicts(instructor_id, date, time_slot, exclude_session_id)` | 해당 강사가 그 (날짜, 시간대)에 배정된 **다른** 세션 목록 반환 (학교/프로그램명 포함). `cancelled` 제외. 경고 표시용 — 실행을 막지 않음 |
| `reschedule_session(session_id, new_date, new_time_slot, changed_by, reason)` | `class_sessions.scheduled_date/time_slot` 갱신 + `session_schedule_history` 에 이전 값 기록. 변경 없음이면 no-op |
| `swap_session_instructor(session_id, new_instructor_id, changed_by, reason)` | `assignments.instructor_id` 갱신 + `assignment_history(change_context='calendar_edit', from/to_instructor_id, reason)` 기록. 동일 강사면 no-op. 배정 없으면 오류 |

충돌은 "완전 차단"이 아니라 **경고 후 담당자 확인** 방식(작업지시서 2-2). 화면에서 변경 전 `instructor_time_conflicts` 를 호출해 결과가 있으면 확인 다이얼로그를 띄우고, "그대로 진행" 시에만 변경 RPC 를 실행한다.

### 1-2. 화면 `/staff/calendar` (staff 전용, 네비에 "캘린더" 탭)

- **`src/lib/calendar.ts`** — 타임존 영향 없는 'YYYY-MM-DD' 달력 유틸 (Date 는 UTC 로만 사용해 KST 파싱 ±1일 오차 방지)
- **월간(6주 그리드) / 주간(7일) 뷰** — `?view=month&y=&m=` / `?view=week&d=`, 이전·다음·오늘 이동
- `scheduled_date` 가 있는 `provisional`·`confirmed` 세션을 카드로: 학교명·프로그램명·시간대·배정 강사명. **최종확정=초록 / 임시배정=주황** 좌측 보더 + 범례
- **드래그 이동**: HTML5 native DnD. 카드를 다른 날짜 칸에 드롭 → 충돌 검사 → (충돌 시) `ConflictDialog` → "그대로 진행" → `reschedule_session`
- **카드 상세 드로어**(우측 슬라이드):
  - 세션 정보 / 현재 배정 강사
  - **일정 변경**: 날짜 + 시간대(자유입력) 편집 → 같은 충돌검사 흐름 → `reschedule_session`
  - **강사 교체**: 전체 활성 강사에서 이름/전문분야로 검색 → 선택(현재 강사는 비활성) → 변경 사유(선택) → 충돌검사 → `swap_session_instructor`
  - **변경 이력**: `session_schedule_history` + `assignment_history` 를 시간순 병합한 타임라인 ("일정 변경: A → B" / "강사 변경 (캘린더에서 교체): 박서연 → 강태호")

RLS: 필요한 테이블 모두 #001·#001보강에서 staff `FOR ALL` 부여됨 → 추가 정책 불필요.

## 4. 발견 / 판단

- **PostgREST 1:1 임베드**: `assignments.session_id` 가 UNIQUE 라 `class_sessions` 에서 `assignments(...)` 임베드가 배열이 아니라 **객체**로 온다. 매핑 코드를 객체 기준으로 수정.
- **충돌 경고 UI**: `window.confirm` 대신 in-DOM `ConflictDialog` 로 구현 — 충돌 세션 목록을 보여줄 수 있고, "담당자 재량으로 계속 진행" 문구를 명시.
- **드래그로는 날짜만 이동**: `time_slot` 이 "3·4교시"/"10:00~12:00" 등 자유서식 TEXT 라 시간 격자에 매핑할 수 없어, 드래그는 날짜 이동만 담당하고 시간대 변경은 카드 상세의 "일정 변경"에서 처리(동일 RPC·이력).
- **`confirm_due_date` 미갱신**: 캘린더에서 provisional 세션의 예정일을 옮겨도 `assignments.confirm_due_date` 는 그대로 둠(작업지시서 범위는 `scheduled_date/time_slot` + 이력만). 예정일 이동 시 최종확정 마감일 재계산이 필요하면 후속 보완 권장.
- **모바일 드래그**: HTML5 DnD 는 데스크톱 기준. staff 업무 PC 사용 전제(회의록 3.1)라 이번 범위에서는 충분.
