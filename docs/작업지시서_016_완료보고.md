## 1. 구현 내용

이번 작업은 화면 변경 없이 **DB 트리거만으로 완결**됩니다 — 지시서 2-3이 명시한 대로 "클라이언트 로직에 의존하지 않게" 하기 위함입니다.

### DB — [`20260913020000_instructor_rating_from_survey.sql`](../supabase/migrations/20260913020000_instructor_rating_from_survey.sql)

- `survey_questions.is_instructor_rating`(기본 false) 추가 후 "강사(진행자)의 설명과 진행은 적절했다." 문항 1개만 `true`로 지정. id가 아니라 이 플래그로 식별하므로 문항 문구를 나중에 고쳐도 연결이 끊기지 않음(지시서 2-1).
- `survey_answers.instructor_id` 추가 — 강사 평가 문항 응답이 들어올 때만 채워지고, **응답 제출 시점의 현재 배정 강사로 고정**된다. 이후 그 세션의 강사가 바뀌어도 이미 저장된 과거 응답의 귀속은 유지되고, 새로 들어오는 응답만 바뀐 시점의 최신 강사에게 귀속됨(지시서 완료기준 마지막 항목).
- `trg_apply_instructor_rating`(`BEFORE INSERT ON survey_answers`) — SECURITY DEFINER 트리거 함수 1개로 완결:
  1. 이 답변이 강사 평가 문항(`is_instructor_rating=true`) + 척도 응답(`answer_rating` not null)인지 확인
  2. `response_id → survey_responses.session_id → assignments.instructor_id`(세션당 1건, 강사교체는 이 row의 instructor_id 를 UPDATE하는 방식이라 항상 "현재" 강사)로 귀속 강사 확정 → `NEW.instructor_id` 세팅
  3. 그 강사에게 이미 귀속된 기존 응답 + 지금 들어오는 응답의 **단순 평균**(시간가중 없음, 지시서 3. 범위 제외)을 계산해 `instructors.rating_avg` 즉시 갱신
- `instructors.rating_avg` 기본값 0 → 3.5로 변경. 강사평가 응답이 하나도 귀속되지 않은 기존 강사 전원(4명 모두 — 이 시점엔 응답 기반으로 계산된 값이 없었음) 을 3.5로 일괄 보정.

## 2. 완료기준 검증 (실제 DB·실제 화면)

미배정 A형 세션(양재초등학교·현장직업체험·로봇공학자)에 김로봇을 배정하고 QR 설문을 실제로 2회 응답 제출 → 강사 교체 → 1회 더 제출 → 최종확정 화면에서 재계산까지 실제로 진행(검증 후 전부 원복).

| 2 | 응답이 들어오면 배정 강사의 `rating_avg` 자동 재계산(수동 조작 없음) | ✅ 김로봇에게 5점 응답 제출 → `rating_avg` 3.50→5.00 즉시 반영(트리거만으로, 별도 API 호출 없음) |
