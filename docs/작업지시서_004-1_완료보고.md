- 일자: 2026-09-12

## 1. 구현 내용

### 문제
기존 `generate_assignment_candidates()`(#004)의 전문분야 점수는 "문자열 완전 일치 → 100/0"이라, 강사가 "로봇SW개발"·"로봇코딩교육"으로 등록돼 있고 세션이 "로봇공학자"를 요구하면 명백히 관련 있는데도 0점 처리됐다(실사용 중 발견 — 김로봇 사례).

### 구조
Claude API 호출은 PL/pgSQL 함수 안에서 할 수 없어(별도 http 확장 도입은 범위 제외), **하드필터는 SQL에 남기고 점수 계산만 TypeScript로 이동**했다.

| 구성요소 | 위치 | 역할 |
| :--- | :--- | :--- |
| `get_matching_candidate_pool()` (신규 SQL) | [migration](../supabase/migrations/20260912000000_specialty_similarity_matching_pool.sql) | 기존 하드필터(`status='active'` + 같은 날짜·시간대 중복배정 제외)를 그대로 재사용해 후보 강사 + 전문분야 목록 반환 |
| `set_session_schedule()` (수정) | 위 migration | 내부에서 하던 `PERFORM generate_assignment_candidates(...)` 호출 제거 — 일정 확정만 담당 |
| `generateAssignmentCandidates()` (신규) | [lib/matching.ts](../src/lib/matching.ts) | 후보 풀 조회 → Claude 배치 호출로 전문분야 유사도(0~100) 산출 → `match_score = 유사도×0.8 + 평점정규화×0.2` 계산 → 상위 3명 `assignment_candidates` 저장 |

### 유사도 판정 (Claude 배치 1회 호출)
- 세션당 **1회**, 후보 전원의 전문분야 목록을 번호 매겨 한 프롬프트에 담아 호출(강사 수만큼 개별 호출 안 함)
- 프롬프트 기준 그대로 반영: 완전동일/사실상 같음 100, 유사 상위분야 70~90, 관련은 있으나 다른 분야 20~40, 무관 0~10
- 강사가 전문분야 여러 개면 그 중 최고점을 사용(Claude 에게 직접 "가장 높은 유사도" 요청)
- **전문분야가 아예 없는 강사는 API 호출 없이 0점** 처리(비용 절감)
- `ANTHROPIC_API_KEY` 미설정이거나 호출/파싱 실패 시 **완전일치 방식으로 자동 폴백** — 강사 배정이라는 핵심 운영 기능이 AI 장애로 완전히 멈추지 않도록 함(#004 원래 규칙을 안전망으로 유지)

### 재사용
초기 임시배정(`confirmSchedule`)과 최종확정 재계산(`startFinalConfirm`) 양쪽 [actions.ts](../src/app/staff/assignments/actions.ts) 에서 동일한 `generateAssignmentCandidates()` 하나를 호출 — 로직 중복 없음.

## 2. 완료기준 검증 (실제 세션으로 브라우저 검증)

실제 미배정 세션(양재초등학교·로봇공학자, 필요 전문분야 "로봇공학자")과 실제 강사 3명(김로봇: 로봇SW개발 등 5개, 박서연: 드론전문가, 김민수: AI교육 등)으로 검증.

| # | 완료기준 | 결과 |
| :-- | :--- | :--- |
| 1 | 정확히 같은 전문분야 → 여전히 최고점 | ✅ 김로봇에게 "로봇공학자"를 정확히 추가하고 재계산 → **80.00점**(=100×0.8+0×0.2, 전문분야 일치 100 정확히 확인). 검증 후 태그 제거로 원복 |
| 2 | 의미상 유사(직업상담↔진로상담류) → 유의미한 점수 | ✅ 김로봇의 실제 전문분야(로봇SW개발·로봇코딩교육 등, "로봇공학자"와 문자열 다름)로 **68.00점**(specialty_match 85 — "유사 상위분야" 구간) |
| 3 | 전혀 무관한 전문분야만 → 낮은 점수 | ✅ 박서연(드론전문가) 44.80점(specialty_match 35), 김민수(AI교육 등) 38.00점(specialty_match 25) — 0점은 아니지만 낮게, "관련은 있으나 다른 분야" 구간과 일치 |
| 4 | 후보 여러 명이어도 세션당 1회 배치 호출 | ✅ 코드 구조상 세션당 Claude 호출 1회(후보 전원을 한 프롬프트에); 후보 3명 재계산이 매번 한 번의 응답 지연 안에 완료됨으로 확인 |
| 5 | 하드필터·최종공식(80/20) 기존과 동일 | ✅ 하드필터 SQL 그대로 재사용(`get_matching_candidate_pool`), 최종 가중치·상위3 로직 TS 에서도 80/20 그대로 |
| 6 | 초기 임시배정·최종확정 재계산 양쪽 동일 로직 | ✅ 같은 세션으로 임시배정→마감일 지난 것으로 표시→최종확정 화면 재계산까지 실제로 진행 — 김로봇 80.00/박서연 44.80/김민수 34.00(강사 수 감소 없이 동일 폴 재계산)으로 초기 계산과 정확히 일치 |

검증 중 만든 임시배정·마감일 조작·임시 전문분야 태그는 전부 되돌려 실제 세션은 원래 상태(미배정, 새 유사도 점수로 재계산됨)로 남겨뒀다.
