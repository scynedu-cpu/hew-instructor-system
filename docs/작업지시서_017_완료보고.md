## 1. 구현 내용

### DB — [`20260913030000_instructor_manager_adjustment.sql`](../supabase/migrations/20260913030000_instructor_manager_adjustment.sql)

- `instructors`에 `manager_adjustment_enabled/score/reason/by/at` 추가 + **`effective_rating` GENERATED ALWAYS AS ... STORED 계산컬럼**(`CASE WHEN enabled AND score IS NOT NULL THEN round(rating_avg*0.7 + score*0.3, 2) ELSE rating_avg END`) — 지시서 그대로 별도 재계산 로직 없이 `rating_avg`나 조정값이 바뀌면 DB가 자동으로 다시 계산.
- `instructor_rating_adjustment_history`(변경 전/후 enabled·score, 사유, 담당자, 시각) 신설. staff 전용 RLS.
- `get_matching_candidate_pool()`(#004-1 이후 초기 임시배정·최종확정 재계산 양쪽이 공용으로 쓰는 함수) 반환 컬럼을 `rating_avg` → **`effective_rating`**으로 변경 — 값의 의미를 명확히 하기 위해 컬럼명 자체를 바꿨고, 이 함수 하나만 고쳐서 양쪽 화면에 자동 적용됨.

### 매칭 로직 — [`matching.ts`](../src/lib/matching.ts)
`CandidatePoolRow.rating_avg` → `effective_rating`으로 교체, 최종 점수 계산(전문분야80%+평점20%)이 이 값을 사용하도록 변경(공식 자체는 무변경, 지시서 3. 범위 제외 그대로).

### 후보 카드 표시 — 매칭 계산과 화면 표시 일관성
`candidate-view.tsx`, `confirm-panel.tsx`, 관련 `page.tsx` 3곳의 강사 조회 select를 `rating_avg`→`effective_rating`으로 바꿔, 후보 카드의 "평점" 표시가 실제 매칭에 쓰인 값과 항상 일치하도록 통일(다른 화면에서 자동점수 자체를 보여주는 목적의 `rating_avg` 표시는 그대로 유지).

### 화면 — 평판 조정 (#008 대리입력 화면에 추가)
[rating-adjustment-section.tsx](../src/app/staff/instructors/%5Bid%5D/edit/rating-adjustment-section.tsx) 신규 — `/staff/instructors/[id]/edit`(담당자 대리입력, 사실상 강사 상세 화면)에 독립 섹션으로 추가:
- 설문 기반 자동점수(`rating_avg`)·현재 매칭 적용점수(`effective_rating`) 읽기전용 표시
- "수동 조정 사용" 토글 → 켜면 조정점수(1.0~5.0)·사유 입력 + "설문 X점×70%+조정 Y점×30%=Z점" 실시간 미리보기
- 저장 시 [`saveRatingAdjustment()`](../src/app/staff/instructors/actions.ts)가 `instructors` 갱신 + `instructor_rating_adjustment_history`에 변경 전/후 기록
- 조정 이력을 시간순으로 나열(누가·언제·무엇을·왜)
