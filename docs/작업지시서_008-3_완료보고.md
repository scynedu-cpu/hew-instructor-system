## 1. 구현 내용

### 새 staff 전용 화면
| 화면 | 내용 |
| :--- | :--- |
| `/staff/instructors/[id]/photo` (신규) | 사진 업로드 — [instructor-photo-section.tsx](../src/components/instructor-photo-section.tsx) |
| `/staff/instructors/[id]/documents` (신규) | 제출 서류 — #003 의 `DocumentsClient` 를 그대로 재사용 |

대리입력 편집 화면(`[id]/edit`)의 "사진 업로드 화면 →" / "제출 서류 입력 화면 →" 버튼은 그대로 두고, 이동 대상만 `/instructor`·`/instructor/documents` → 위 두 staff 화면으로 교체했다.

### 로직 재사용 (신규 작성 없음)
- 사진: `uploadPhoto()`([instructor/actions.ts](../src/app/instructor/actions.ts)) 그대로 재사용 — Storage 업로드 + `instructors.photo_url` 갱신
- 서류: `uploadDocument()`/`deleteDocument()`([instructor/documents/actions.ts](../src/app/instructor/documents/actions.ts)) 그대로 재사용 — 업로드일 입력 → DB 트리거(`instructor_doc_expiry`)가 만료일 자동계산, `DOC_STATUS_*`([lib/documents.ts](../src/lib/documents.ts))가 정상/임박/만료 배지 계산
- 두 액션 모두 `getInstructorContext()` 로 `instructorId` 를 판별하는데, 이 함수는 staff 대리입력 모드일 때 **`PROXY_INSTRUCTOR_COOKIE` 만으로** 판별하고 `app_accounts` 를 조회하지 않음(#008-1 에서 이미 확인된 설계) — 그래서 이 두 액션을 staff 화면에서 그대로 불러써도 계정 유무와 무관하게 동작함

### 새로 만든 것
- `instructor-photo-section.tsx` — staff 화면용 사진 UI(강사 본인 화면의 "기본 프로필" 카드에서 사진 부분만 분리·재사용 형태로 새로 작성, 업로드 로직 자체는 기존 액션 그대로 호출)
- `lib/instructor-documents.ts` — 서류 목록 + 서명 URL 조회를 공용 함수(`loadInstructorDocuments`)로 분리, 강사 본인 화면(`/instructor/documents`)도 이걸로 갈아끼움(중복 제거)
- `actions.ts` `enterInstructorProxy()` — "사진 업로드"/"제출 서류 입력" 버튼 클릭 시 **그 순간** `PROXY_INSTRUCTOR_COOKIE` 를 편집 중인 강사 id 로 다시 맞춰준 뒤 이동. (편집 화면에 어떤 경로로 들어왔든 — 목록의 "대리입력" 버튼, #008-2 의 업로드 우선 생성 후 자동 이동 등 — 사진/서류 화면에서 쿠키가 다른 강사를 가리키는 일이 없도록 하는 안전장치. 기존 `pickInstructorForEdit` 은 그대로 유지)
