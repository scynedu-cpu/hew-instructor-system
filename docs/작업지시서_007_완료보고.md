## 1. 구현 내용

### 1-1. 마이그레이션 `20260910030000_payment_settlement.sql`

기존 `payments`(assignment 단위) 는 참조가 없어 DROP 후 재생성.

| 테이블 | 내용 |
| :--- | :--- |
| `payment_rate_settings` | 조직 전체 단일 단가 이력. `rate`, `effective_from`, `note`, `created_by`. 변경 시 새 row |
| `payments` (재설계) | 강사·기간 단위 정산. `instructor_id`, `period_start/end`, `quantity`, `rate`(스냅샷), `amount`, `payment_status`(pending/paid), `settled_by/at`, `paid_by/at` |
| `payment_items` | 정산에 포함된 개별 강의. `payment_id`, `lecture_confirmation_id **UNIQUE**` → 강의 1건은 최대 1 정산에만 (중복정산 방지) |

| 함수 (SECURITY INVOKER, staff RLS) | 역할 |
| :--- | :--- |
| `current_payment_rate()` | `effective_from <= 오늘` 중 최신 단가 |
| `preview_lecture_payments(start, end)` | 기간 내 완료 강의 중 아직 어떤 payment_items 에도 없는 건을 강사별 건수로 |
| `settle_lecture_payments(start, end, by)` | 위 대상을 강사별 집계 → `payments`(quantity/rate/amount) 생성 + `payment_items` 연결. 반환: 생성된 payments 수 |
| `mark_payment_paid(id, by)` | `payment_status='paid'`, `paid_at=now()`. 이미 paid 면 거부 |

신규 3개 테이블 staff `FOR ALL` 정책 부여.

### 1-2. 화면 `/staff/payments` (staff 전용, 새 "강사료 정산" 탭)

- **단가**: 현재 단가 표시 + "단가 변경"(새 단가·적용일·메모 → 새 row) + 변경 이력
- **정산 집계**: 기간 지정(기본 = 이번 달) → **「대상 미리보기」**(강사별 건수) → **「이 기간 정산 집계」** → `settle_lecture_payments`
- **정산 내역**: 강사·기간·건수·단가·금액·상태 목록, 목록에서 바로 "지급완료 처리"
- **정산 상세** `/staff/payments/[id]`: 기간·건수·단가·금액·집계/지급 시각 + **포함된 강의 목록**(강의일·학교·프로그램·시수) + "지급완료 처리"

`lecture_confirmations`(완료 강의 확인) 를 만드는 화면은 이 작업 범위 밖 — 정산은 그 데이터 위에서 동작.

## 4. 발견 / 판단

- **단가 스냅샷**: `payments.rate` 를 집계 시점 값으로 고정 저장 → 이후 단가를 바꿔도 과거 정산 금액 불변 확인.
- **중복정산 방지**: `payment_items.lecture_confirmation_id UNIQUE` 로 DB 레벨 보장. 집계 쿼리는 `NOT EXISTS payment_items` 로 이미 포함된 건 제외.
- **완료 강의 입력**: `lecture_confirmations` 를 채우는 "강의 완료 확인" 화면은 어느 작업지시서에도 없음 → #007 은 정산만. 필요 시 후속 작업지시서.
- **실제 송금**: 범위대로 `payment_status` 상태 관리까지만. 화면에도 "실제 송금은 담당자가 직접" 명시.
