## 1. 구현 내용

### DB — [`20260912020000_survey.sql`](../supabase/migrations/20260912020000_survey.sql)

- `survey_questions` — 문항. `question_type`(`rating_5`/`single_choice`/`short_text`/`long_text`), `options`(단일선택 선택지 배열), `display_order`, `is_active`. "삭제"는 `is_active=false` 전환만 하므로 기존 응답과의 연결이 끊기지 않음.
- `survey_links` — 세션(`class_sessions`) 당 1개(`session_id` UNIQUE), 랜덤 `token`.
- `survey_responses` — 개별 응답 1건 = 1행(`session_id`만 연결, 식별정보 없음).
- `survey_answers` — 응답별 문항 답변(`answer_rating` 또는 `answer_text`).
- 초기 문항 9개를 실제 설문지 원본 기준으로 시드: 신분·성별·학년 + 5점 척도 5문항 + 기타의견. 학교명·참가 프로그램은 세션에 이미 있어 별도 문항으로 안 만듦(지시서 참고).

**RLS**
- `survey_questions`: staff 전체 + `is_active=true`는 누구나(anon 포함) 조회.
- `survey_links`: staff만. 공개 페이지는 링크 목록을 절대 조회하지 않고, 아래 `get_survey_context()` RPC로 토큰 1건만 조회.
- `survey_responses`/`survey_answers`: staff만 직접 조회·수정 가능. 익명 제출은 테이블 RLS로 직접 열어주지 않고 `submit_survey_response()` RPC(SECURITY DEFINER)로만 받음 — 응답 1건+답변 N건을 한 트랜잭션으로 묶고 활성 문항인지 서버에서 검증하기 위함. 익명은 이 RPC로도 자기 응답을 되읽을 수 없음(완전 익명 요건과 정확히 맞음).

**RPC**
- `get_survey_context(p_token)` — 토큰 → 세션 컨텍스트(학교명/프로그램명/예정일). anon 실행 허용.
- `submit_survey_response(p_token, p_answers jsonb)` — 응답 제출. anon 실행 허용.

## 2. 완료기준 검증

### 실제 화면 (브라우저)
1. `/staff/survey-questions`에서 문항 추가 → 목록 맨 끝에 반영, 순서 변경(▲) → 인접 문항과 자리 교체 정상, 인라인 수정 → 문구 반영, "삭제" → `비활성` 배지로 전환(응답 연결 유지, 완전 삭제 아님), "다시 활성화"로 원복 — 모두 실제 클릭으로 확인 후 테스트 문항은 정리.
2. 캘린더(양재초등학교·전환기 프로그램 세션) 카드 상세 → "설문 QR 보기" 클릭 → QR코드 생성·표시. 패널을 닫고 다시 열어 재클릭 → **동일한 링크**(`/survey/d7862429-...`) 재사용 확인.
3. 생성된 링크를 새 탭에서 로그인 없이 접속 → "양재초등학교 · 전환기 프로그램 · 2026-09-11" 컨텍스트와 활성 문항 9개가 순서대로 렌더링. 전체 응답 후 제출 → "감사합니다" 화면 전환.
4. DB 직접 조회로 `survey_responses` 1건(`session_id`만, 이름 등 없음) + `survey_answers` 9건이 각 문항 타입에 맞게(`answer_rating`/`answer_text`) 정확히 저장됨을 확인 → 검증 후 삭제.
