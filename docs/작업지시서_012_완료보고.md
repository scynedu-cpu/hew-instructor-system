## 1. 구현 내용

### DB
- [`20260912010000_lecture_completion.sql`](../supabase/migrations/20260912010000_lecture_completion.sql) — 강의확인서 파일을 담을 비공개 Storage 버킷 `lecture-confirmations` 신설(staff 전용 RLS). `lecture_confirmations` 테이블 자체와 staff RLS는 #001에서 이미 있어 추가 마이그레이션 불필요.

### 화면 — #005 캘린더 카드 상세에 얹음(신규 화면 없음)
[`session-detail-panel.tsx`](../src/app/staff/calendar/session-detail-panel.tsx)에 "강의 완료 처리" 섹션 추가:
- `session.session_status === "confirmed"`일 때만 노출(지시서 2-1)
- 실제 강의일(기본값 = `scheduled_date`) · 실제 강의 시간 · 강의확인서 파일 입력
- 저장 시 `completeSession()`([calendar/actions.ts](../src/app/staff/calendar/actions.ts)) 호출

### 처리 로직 (`completeSession`)
1. 세션이 `confirmed` 상태인지 재확인(클라이언트 조건과 별개로 서버에서도 검증)
2. `assignments` 에서 `session_id` 로 `assignment_id` 조회
3. 강의확인서를 `lecture-confirmations` 버킷에 업로드
4. `lecture_confirmations` insert(`assignment_id`, `actual_date`, `actual_hours`, `file_url`)
5. `class_sessions.session_status = 'completed'` 갱신
6. 기존 캘린더 패널의 `onChanged` 패턴 재사용 — 저장 성공 시 패널이 닫히고 캘린더가 새로고침됨. 캘린더 조회 쿼리가 원래 `session_status IN ('provisional','confirmed')` 만 가져오므로, `completed` 로 바뀐 세션은 새로고침 후 캘린더에서 자연히 사라짐 → 버튼도 다시 못 봄(중복 완료 처리 방지, 지시서 2-3/완료기준 4)
