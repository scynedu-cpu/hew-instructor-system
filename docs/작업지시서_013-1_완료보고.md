## 1. 구현 내용

### DB — [`20260913010000_survey_question_groups.sql`](../supabase/migrations/20260913010000_survey_question_groups.sql)

- `survey_question_groups`(A~E 5개, 라벨은 지시서 표 그대로) 신설.
- `survey_questions`에 `scope`(`common`/`group`) · `survey_group` 컬럼 추가 + 일관성 CHECK. 기존 #013 초기 9개 문항(신분/성별/학년/5점척도5/기타의견)은 **삭제하지 않고 비활성화**(이미 응답이 쌓여 있어 FK 보존 필요) 후 지시서 원문 그대로 새 문항 33개(공통 8 + 그룹별 5×5) 등록.
- `programs.survey_group` 컬럼 추가 → 기존 등록된 프로그램(전환기 프로그램→E, 직업인특강→B, 현장직업체험 5종→A, 총 7개)을 표대로 채운 뒤 `NOT NULL` 확정. C/D형·마을공동체연계프로그램 등은 현재 DB에 해당 프로그램이 없어 매핑 대상이 없고, 그룹 자체는 이미 등록해뒀으니 향후 신규 등록 시 담당자가 지정하면 됨(3-2 방침 그대로).
- `survey_link_questions`(세션별로 확정된 문항 구성의 스냅샷) 신설. **회귀 방지**: 이 마이그레이션 이전에 이미 발급돼 있던 survey_links(9/11 세션)는 이 개념이 없었으므로, 그 시점에 활성이었던 예전 9개 문항을 그대로 백필해 기존 QR이 문항 구조 변경 후에도 동일하게 계속 작동하도록 함.
- `get_survey_link_questions(token)` RPC 신규(anon 허용, SECURITY DEFINER) — 공개 응답 페이지가 이제 `survey_questions`를 직접 조회하지 않고 이 함수로 "확정된 구성"만 읽음.
- `submit_survey_response()` 검증 기준을 "활성 문항인지"에서 "그 토큰의 확정 구성(`survey_link_questions`)에 포함돼 있는지"로 변경 — 확정 후 문항이 비활성화/그룹변경 돼도 이미 발급된 QR은 계속 정상 동작.

3. "확정"하면 [`confirmSurveyLink()`](../src/app/staff/calendar/actions.ts)가 `survey_links` + `survey_link_questions`를 생성.
