## 1. 구현 내용

### DB — [`20260913000000_instructor_unavailable_periods.sql`](../supabase/migrations/20260913000000_instructor_unavailable_periods.sql)

- `instructor_unavailable_periods`(id, instructor_id, start_date, end_date, reason, created_at) 신설. `end_date >= start_date` CHECK, RLS는 경력/자격증과 동일 패턴(staff 전체 + 강사 본인).
- **매칭 하드필터 확장** — `get_matching_candidate_pool()`(#004-1에서 초기 임시배정·최종확정 재계산 양쪽이 공용으로 쓰는 함수)의 기존 "시간대 중복" 조건에 `NOT EXISTS (... instructor_unavailable_periods ... scheduled_date BETWEEN start_date AND end_date)` 조건을 추가. 함수 하나만 고쳐서 양쪽 화면에 자동 적용됨(반환 타입 동일 → `CREATE OR REPLACE`).
- **캘린더 경고 확장** — `instructor_time_conflicts()`를 확장(반환 컬럼 추가로 `DROP` 후 재생성)해 기존 "시간대 중복" 결과에 `UNION ALL`로 "불가기간 겹침" 결과를 추가. `conflict_type`(`schedule`/`unavailable`) 컬럼으로 구분.

### 화면 1 — 강사 정보 입력 화면 (#003: `/instructor`)
[unavailable-section.tsx](../src/app/instructor/unavailable-section.tsx) — 경력·자격증과 동일한 `EditableList`(즉시 추가/수정/삭제) 패턴으로 "강의 불가기간" 섹션 추가. [`instructor/actions.ts`](../src/app/instructor/actions.ts)에 addUnavailable/updateUnavailable/deleteUnavailable 추가(종료일<시작일 검증 포함).

### 화면 2 — 담당자 대리입력 화면 (#008: `/staff/instructors/[id]/edit`)
실제 담당자가 쓰는 주 경로. 이 화면은 `/instructor`와 다른 별도 컴포넌트(`InstructorProfileForm`, 경력/자격증/전문분야를 로컬 state로 모아뒀다가 "저장" 한 번에 일괄 반영하는 방식)라 여기에도 동일하게 "강의 불가기간" `RowSection`을 추가했다. [`staff/instructors/actions.ts`](../src/app/staff/instructors/actions.ts)의 `replaceInstructorDetails()`(경력/자격증/전문분야를 delete-then-insert로 전체 교체하는 공용 함수)에 불가기간도 동일한 방식으로 추가 — 신규 생성(`createInstructorProfileFull`)·기존 수정(`saveInstructorProfile`) 양쪽에 자동 적용됨.

### 화면 3 — 캘린더 경고 (#005 재사용)
[conflict-dialog.tsx](../src/app/staff/calendar/conflict-dialog.tsx)가 `conflict_type`에 따라 다르게 표시("강사 불가기간과 겹침 (날짜 · 사유)" vs 기존 세션 중복 표시). [`lib/types.ts`](../src/lib/types.ts)에 `conflictReasonText()` 헬퍼를 추가해 캘린더 3곳(드래그 이동/일정변경/강사교체)의 경고 문구가 "이미 배정됨" / "불가기간과 겹침" / "둘 다"를 상황에 맞게 자동으로 표시하도록 통일. 코드 변경 없이 `instructor_time_conflicts` RPC 결과가 그대로 흘러가므로 세 곳 다 자동으로 적용됨.

## 2. 완료기준 검증 (실제 DB·실제 화면)

1. **불가기간 추가/수정/삭제** — `/staff/instructors/[id]/edit`(담당자 대리입력, 실사용 경로)에서 김로봇 강사에게 `2026-09-20~2026-09-30 · 해외 출장`을 등록 → 저장 → DB에 정확히 반영 확인.
2. **매칭 하드필터 — 겹치는 강사 제외** — 2026-09-25 로봇공학자 세션의 **초기 임시배정**에서, 불가기간 등록 전엔 김로봇이 1순위(68.00점)였는데 등록 후 재계산하니 **김로봇이 후보 3명에서 완전히 사라짐**(박서연 48.80 → 김민수 46.00 → 이진로 4.00으로 교체).
3. **겹치지 않는 강사는 정상 포함** — 위 결과에서 박서연·김민수·이진로는 그대로 후보에 남아 정상 동작.
4. **초기 배정·최종확정 재계산 양쪽 동일 적용** — 위 세션을 박서연으로 임시배정 후 최종확정 화면에서 "다시 확정"(재계산) → 동일하게 김로봇 제외, 순위도 동일(박서연→김민수→이진로).
5. **캘린더 경고** — 9/25 세션 상세에서 "강사 교체"로 김로봇 선택 후 교체 시도 → `⚠ 강사 교체 — 배정 충돌 / 김로봇 님이 2026-09-25 10:00~11:30에 강의 불가기간과 겹칩니다. · 강사 불가기간과 겹침 (2026-09-25 · 해외 출장)` 경고가 정확히 표시됨. "취소"로 실제 반영은 하지 않음.

검증에 쓴 배정(박서연 임시배정)과 테스트 불가기간은 검증 후 모두 삭제하고 세션을 원래 `unassigned` 상태로 복원했습니다.
