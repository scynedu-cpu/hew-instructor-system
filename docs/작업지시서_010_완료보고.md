### "업데이트 필요" 판정 (지시서 2-1 그대로)
[dashboard/page.tsx](../src/app/staff/instructors/dashboard/page.tsx) 에서 서버 사이드로 계산:

1. **서류 상태**: `instructor_documents.expires_at` 을 `computeStatus()`([lib/documents.ts](../src/lib/documents.ts))로 매 요청마다 다시 계산해서 `expiring_soon`/`expired` 판정. ⚠ 저장된 `status` 컬럼은 값이 바뀔 때(업로드 시점)만 계산되고 이후엔 시간이 지나도 갱신되지 않는 stale 컬럼(#006 완료보고에서 이미 확인된 사실 — 그래서 #006 배치가 매일 `refresh_instructor_document_status()` 로 다시 계산함). 대시보드는 볼 때마다 정확해야 하므로 컬럼 대신 `expires_at` 원본으로 그때그때 재계산 — 배치 실행 여부와 무관하게 항상 정확함
2. **필수정보 미비**: `instructor_career_history`/`instructor_certifications`/`instructor_specialties` 건수를 각각 세어 셋 다 0일 때만 "미비"
3. **계정 미발급**: `app_accounts` 를 `instructor_id` 로 조인해서 매핑이 없으면 "미발급" (로그인/가입 여부는 안 봄 — 지시서 그대로 "row 존재 여부"만)

한 강사가 서류를 여러 건 냈으면 가장 급한 상태(만료 > 임박 > 정상)로 배지 표시.

### 화면 구성
- 요약 카드 3개(서류 만료임박·만료 / 정보 미비 / 계정 미발급) — 중복 포함 카운트
- "업데이트 필요만 보기" 체크박스(기본 켜짐) — 세 조건 중 하나라도 해당하면 노출
- 이름·전문분야 검색
- 테이블: 성명(링크)·전문분야·서류상태 배지·정보완성도 배지·계정상태 배지
- 성명 클릭 → `/staff/instructors/[id]/edit` (대리입력 화면, #008) — 별도 쿠키 설정 없이 바로 이동 가능(그 화면은 URL 의 `id` 로만 강사를 찾고 쿠키에 의존하지 않음, #008-3 에서 이미 확인된 구조)

## 2. 완료기준 검증 (실제 데이터로 브라우저 검증)

기존 실사용 강사 4명(김로봇·김민수·박서연·이진로) + "정보 미비"·"서류 만료" 각 조건을 검증할 테스트 강사 2명을 추가해 확인 후 삭제로 원복.

| # | 완료기준 | 결과 |
| :-- | :--- | :--- |
| 1 | 전체 강사 이름·전문분야 조회 | ✅ 필터 끄면 6명(기존 4 + 테스트 2) 전부, 전문분야 정상 표시 |
| 2 | `expiring_soon`/`expired` 배지 표시 | ✅ 이력서 발급일 2020-01-01(3년 유효) 업로드한 테스트 강사에게 "만료" 배지 정확히 표시 |
| 3 | 경력·자격증·전문분야 전부 0건 → "정보 미비" | ✅ 방금 생성한(아무것도 안 채운) 테스트 강사가 "미비"로 표시. 전문분야만 있는 강사는 "완료"로 정상 구분 |
| 4 | `app_accounts` 매핑 없음 → "계정 미발급" | ✅ 계정 있는 김민수만 "발급됨", 나머지 5명(계정 없음) 전부 "미발급" |
| 5 | 필터 온/오프 정상 동작 | ✅ 켜면 조건 해당 5명만(김민수 제외), 끄면 6명 전체 |
| 6 | 요약 카드 인원수 = 목록과 정확히 일치 | ✅ 서류 1명/정보 미비 1명/계정 미발급 5명 — 전체 6행을 직접 세어 각각 정확히 일치 확인 |
| 7 | 강사 행 클릭 → 대리입력 화면 이동 | ✅ "박서연" 클릭 → `/staff/instructors/{id}/edit` 정상 이동 |
