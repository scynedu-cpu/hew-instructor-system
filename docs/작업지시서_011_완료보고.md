## 1. 구현 내용

### 신규 API — `src/app/api/ai/specialty-suggestions/route.ts`
- DB 를 읽거나 쓰지 않는 순수 변환 API. 화면에 입력된(저장 전이어도 되는) 경력/자격증 텍스트 + 이미 등록된 전문분야 목록을 받아 Claude 에 전달, 전문분야 후보 3~5개를 JSON 배열로 받아 반환
- 이미 등록된 전문분야와 겹치는 후보는 프롬프트로 지시 + **서버에서 한 번 더 필터링**(모델이 지시를 놓쳐도 항상 보장)
- `requireUser()` 로 staff/instructor 역할만 허용(school 은 사용 대상 아님)
- `ANTHROPIC_API_KEY` 미설정 시 기존 AI 자동채움(#008)과 동일한 원칙 — 에러 안내 또는 `AI_AUTOFILL_MOCK=1` 일 때 텍스트 기반 간단 모의 추천

### 공용 컴포넌트 — `src/components/specialty-recommendations.tsx`
- "AI 추천" 버튼(경력·자격증 둘 다 없으면 비활성화 + 안내 문구) → 클릭 시 위 API 호출 → 점선 테두리 "+ 키워드" chip 으로 후보 표시
- chip 클릭 시에만 부모의 `onAdd` 콜백 호출(정식 태그로 추가) — 클릭 전까지는 아무것도 저장되지 않음
- 클릭한 chip 은 그 즉시 추천 목록에서 사라짐(다시 겹쳐 보이지 않게)

### 적용 (#003·#008 공통, 지시서 2-4)
| 화면 | 연결 방식 |
| :--- | :--- |
| `/instructor` — `specialty-section.tsx`(#003, 본인 입력) | `career`/`certs` prop 추가, `onAdd`→기존 `addSpecialty()` 서버 액션(클릭 즉시 저장, 기존 방식 그대로) |
| `instructor-profile-form.tsx`(#008, 담당자 대리입력) | 화면에 입력 중인(아직 미저장) `careerRows`/`certRows` 그대로 전달, `onAdd`→로컬 `specs` state 에 추가(기존처럼 전체 "저장" 버튼 눌러야 DB 반영) |

두 화면 다 각자의 기존 저장 방식을 그대로 따르고(즉시저장 vs 일괄저장), 추천 로직 자체(`SpecialtyRecommendations`)는 완전히 동일한 컴포넌트를 공유.
