## 1. 구현 내용 (staff 전용, 신규 화면 2개 — 별도 마이그레이션 없음)

기존 #013 테이블(`survey_questions`/`survey_responses`/`survey_answers`)에 이미
staff 전체조회 RLS가 있어 이번엔 화면만 추가하면 됐다. 지시서 2-3 방침대로
집계는 캐싱·배치 없이 화면 진입 시마다 `survey_answers`를 직접 조회해서 계산.

### 목록 — [`/staff/survey-results`](../src/app/staff/survey-results/page.tsx)
- `class_sessions`을 학교/프로그램 join해서 한 행씩, `survey_responses`를
  전체 조회해 세션별 건수를 JS에서 집계(Map)해 붙임 — 세션 수가 많지 않아
  별도 서버 집계 함수 없이 단순 조회 2번으로 충분.
- 학교/프로그램 `<select>` + 시작일·종료일 `<input type=date>`를 담은
  일반 GET 폼(자바스크립트 없이 쿼리스트링으로 필터, 기존 `/staff/requests`
  상태 탭과 같은 서버 컴포넌트 필터 패턴).
- 응답 0건인 세션도 숨기지 않고 "응답 없음"으로 표시(지시서 2-1).

### 상세 — [`/staff/survey-results/[sessionId]`](../src/app/staff/survey-results/%5BsessionId%5D/page.tsx)
- 해당 세션의 `survey_responses` id 목록 → `survey_answers`를 `question:survey_questions(...)` join으로 한 번에 조회 → `question_id`별로 그룹핑.
- **문항 선정 방식**: "활성 여부"가 아니라 "이 세션에 실제 답변이 있는 문항"만 모음 → 비활성화된 과거 문항도 응답이 있으면 자동으로 나타남(지시서 2-3), 반대로 현재는 활성이어도 이 세션에 응답이 없으면 표시 안 함(당연히 보여줄 값이 없음).
- 문항 유형별 표시:
  - `rating_5` → 평균(소수 둘째자리, `toFixed(2)`) + 응답 건수
  - `single_choice` → 선택지별 응답자 수·비율 막대그래프. 문항의 **현재** 선택지 순서로 먼저 나열하고, 선택지 구성이 바뀐 뒤에도 남아있는 과거 응답값(현재 옵션에 없는 값)은 뒤에 이어서 표시(데이터 유실 없음).
  - `short_text`/`long_text` → 응답 텍스트를 번호만 붙여 나열(익명이라 순서 외 식별정보 없음).

### 네비게이션
[`staff/layout.tsx`](../src/app/staff/layout.tsx) 최상위 메뉴에 "캘린더" 다음으로 "설문 결과" 추가(문항 관리·프로그램 관리 같은 설정성 메뉴가 아니라 캘린더·배정처럼 실데이터를 보는 화면이라 "관리자" 하위가 아닌 최상위로 배치).
