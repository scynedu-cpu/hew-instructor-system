## 1. 구현 내용

### 1-1. 매칭 / 배정 함수 (마이그레이션 `20260909060000_matching_and_assignment.sql`)

모두 `SECURITY INVOKER` → 호출자(staff)의 RLS 가 그대로 적용. `authenticated` 롤에 EXECUTE 부여.

| 함수 | 역할 |
| :--- | :--- |
| `generate_assignment_candidates(session_id)` | 매칭 함수 본체. ① 하드필터(같은 `scheduled_date`+`time_slot` 에 이미 다른 세션에 배정된 강사 제외, `status='active'` 만) ② 점수 `match_score = specialty_match*0.8 + rating_avg/5*100*0.2` (specialty_match: `required_specialty` 와 정확히 일치하는 `instructor_specialties` 있으면 100, 없으면 0) ③ 상위 3명을 `assignment_candidates` 에 rank 1~3 으로 **삭제 후 재기록** |
| `set_session_schedule(session_id, date, time_slot)` | 초기 배정 화면 — `unassigned` 세션의 예정일/시간대 확정 후 매칭 함수 실행 |
| `assign_provisional(session_id, instructor_id, candidate_id, assigned_by)` | 후보 3명 중 1명 선택 → `assignments` row(`assignment_type='provisional'`, `selected_from_candidate_id`, `provisional_at=now()`, `confirm_due_date = scheduled_date - interval '1 month'`) 생성 + `class_sessions.session_status='provisional'`. 후보 검증(해당 세션의 rank 1~3 중 하나) 포함 |
| `assignments_pending_final_confirm()` | `provisional` AND `confirm_due_date <= CURRENT_DATE` (PostgREST 에서 날짜 비교가 까다로워 함수로 제공) |
| `confirm_assignment(assignment_id, instructor_id, changed_by, reason)` | 최종확정. **유지**(instructor 동일) → `assignment_type='confirmed'`, `confirmed_at=now()`. **변경** → `instructor_id` 갱신 + `is_changed_at_final=true` + `assignment_history(change_context='final_confirm', from/to_instructor_id, reason)` 기록. 변경 시 새 강사 하드필터 재확인. 공통으로 `class_sessions.session_status='confirmed'` |

### 1-2. 보강 마이그레이션 `20260909070000_candidate_fk_on_delete_set_null.sql`

`assignments.selected_from_candidate_id` FK 를 `ON DELETE SET NULL` 로 변경.
→ 최종확정 단계에서 매칭 함수를 **재실행**(작업지시서 2-3)하면 기존 후보 행을 지우는데,
이미 임시배정된 세션은 그 후보를 FK 로 참조하고 있어 `DELETE` 가 막혔음(검증 중 발견).
후보 테이블은 추천 스냅샷이므로 재계산 시 이전 선택 링크는 끊어져도 무방(배정 강사·담당자·시각은 `assignments` 에 유지).

| 경로 | 내용 |

| `/staff/assignments/[sessionId]` | 세션 상세. 예정일/시간대 확정 폼(학교 희망일자 빠른선택 또는 직접 입력) → 확정 시 매칭 실행 → 후보 3명(순위·강사·전문분야칩·평점·`match_score`·일치배지) 라디오 선택 → 「선택한 강사로 임시배정」. 이미 배정된 세션은 배정 요약 표시 |

## 4. 발견 / 판단

- **후보 재계산 시 FK 충돌**: 위 1-2 참조. `ON DELETE SET NULL` 로 해결.
- **점수 상위 3명 채우기**: 조건에 맞는(전문분야 일치) 강사가 3명 미만이면 전문분야 불일치(점수 0.x) 강사가 rank 를 채운다. 작업지시서 "match_score 상위 3명" 문구대로이며, 화면에 "전문분야 불일치 0" 배지로 명확히 표시. (강사 풀이 커지면 자연 해소)
- **`status='active'` 하드필터 추가**: 작업지시서엔 시간대 중복만 명시됐으나, 비활성 강사를 추천하지 않도록 활성 강사만 후보 대상으로 삼음(회의록 2.2 강사 등급/우선순위 취지).
- **초기 예정일**: 신청 승인 시 `class_sessions.scheduled_date` 에 희망일자 첫 값이 이미 복사되어 있음. 이 경우에도 담당자가 "예정일 확정" 을 눌러야 매칭이 돌도록 함(시간대 조정 여지 + 명시적 트리거).
