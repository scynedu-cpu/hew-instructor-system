## 0. 사용자와 확인한 판단 기준

작업 전 아래 3가지를 직접 확인받아 진행했습니다.

1. **자동화 범위**: 담당자 수동 승인만 생략. 강사 매칭·배정은 지금처럼 담당자가 직접 진행(자동 임시배정까지는 하지 않음).
2. **캘린더 노출**: 강사 배정 전(미배정) 상태도 캘린더에 즉시 "강사 미배정" 카드로 노출.
3. **자동승인 전 안전장치**: "다른 학교"의 기존 일정과 **같은 날짜**면(시간대 표기가 학교마다 자유 텍스트라 정확 비교가 어려워) 무조건 겹침으로 보고 자동승인을 보류 — 승인을 먼저 하고 나중에 취소하는 방식이 아니라, 겹치면 애초에 자동승인하지 않고 담당자 검토로 남김.

## 1. 구현 내용

### 자동승인 판단 — [`schedule-overlap.ts`](../src/lib/schedule-overlap.ts) + [`school/actions.ts`](../src/app/school/actions.ts)
학교 본인 제출(#002)과 담당자 대리입력(#008/#009)이 공용으로 쓰는 `saveRequestWithItems()`에 자동승인 판단을 추가:
- 신청서의 모든 프로그램 항목에 희망일자가 있고(날짜 미정 항목이 하나도 없고),
- 그 날짜들이 **다른 학교**의 기존 일정(`class_sessions`, 취소 제외)과 하나도 겹치지 않으면
- 기존 `approve_session_request()`(#002) RPC를 그대로 호출해 즉시 승인 — 수업(class_sessions, `unassigned`)이 곧바로 생성됩니다.
- 하나라도 날짜 미정이거나 다른 학교 일정과 겹치면 지금과 동일하게 `제출됨` 상태로 남아 담당자 검토를 거칩니다.

자동승인은 `reviewed_by = "시스템(자동승인)"`으로 기록해 담당자 수동 승인과 구분됩니다.

**보안 이슈 발견·수정**: `approve_session_request()`는 `class_sessions`에 INSERT하는데 이 테이블 RLS는 staff 전용이라, 학교 계정 권한으로 그대로 호출하면 "row-level security policy" 오류로 막힙니다. 이 함수 자체를 RLS 우회로 바꾸면 악의적 호출로 타 학교 신청서를 승인시킬 수 있는 구멍이 생기므로, 함수는 그대로 두고 — 이미 `saveRequestWithItems()` 안에서 "이 신청서가 opts.schoolId 소유"라는 게 검증된 뒤 시점에 한해 — **서비스 롤 클라이언트로 그 한 건만** 승인 RPC를 호출하도록 처리했습니다(`createAdminClient()`, 기존 강사 초대 기능에서 쓰던 것과 동일 패턴).

### 겹침 경고 표시 — [`staff/requests/page.tsx`](../src/app/staff/requests/page.tsx), [`[id]/page.tsx`](../src/app/staff/requests/[id]/page.tsx)
대기중(제출됨/검토중) 신청 건은 조회 시점에 겹침을 다시 계산해 목록엔 "⚠ 일정 겹침" 배지(호버 시 상세), 상세 화면엔 "어느 학교의 며칠 일정과 겹치는지"를 보여줘 담당자가 바로 판단할 수 있게 했습니다. 자동승인된 건도 "자동승인됨(다른 학교 일정과 겹치지 않음)"으로 수동승인과 구분 표시됩니다.

### 캘린더 — [`calendar/page.tsx`](../src/app/staff/calendar/page.tsx), [`calendar-client.tsx`](../src/app/staff/calendar/calendar-client.tsx), [`session-detail-panel.tsx`](../src/app/staff/calendar/session-detail-panel.tsx)
- 조회 상태 필터에 `unassigned` 추가(기존엔 강사가 정해진 건만 보였음).
- 미배정 세션은 빨간색 카드 + "배정 필요" 배지로 시각적으로 구분, 범례에도 "강사 미배정" 항목 추가.
- 상세 패널: 배정된 강사가 없으면 기존 "강사 교체" 섹션(배정이 이미 있어야 동작하는 기능) 대신 "아직 강사가 배정되지 않았습니다 → 배정하러 가기"로 #004 배정 화면 해당 건으로 바로 연결. 일정 변경(날짜 이동)은 배정 여부와 무관하게 기존처럼 가능.

## 2. 검증 (실제 데이터)

1. 양재초등학교로 로그인 → 겹치는 일정이 없는 날짜로 신청 → **제출 즉시 "승인" 상태로 전환**, "신청이 접수되어 바로 수업 일정에 반영되었습니다" 안내 확인. DB에서 `class_sessions.session_status='unassigned'`, `reviewed_by='시스템(자동승인)'` 정확히 확인.
2. 캘린더에서 해당 날짜에 **빨간 "배정 필요" 카드**가 바로 노출됨을 확인. 클릭 → 상세패널에 "아직 강사가 배정되지 않았습니다 → 배정하러 가기" → 클릭 시 #004 배정 화면의 해당 건으로 정확히 이동.
3. 같은 날짜로 **다른 학교**(매헌중학교, 담당자 대리입력) 신청 제출 → **자동승인되지 않고 "제출됨" 상태로 유지**됨을 확인. 신청 목록에 "⚠ 일정 겹침" 배지, 상세 화면에 "2026-11-10 — 양재초등학교 · 드론전문가"라는 구체적 겹침 안내 확인.
4. 이 겹침 건을 담당자가 직접 "승인" 버튼으로 승인 → 정상 처리되고 캘린더에도 같은 날짜에 두 학교 카드가 나란히 표시됨을 확인(자동승인이 막혔을 뿐, 기존 수동 검토·승인 흐름은 그대로 작동).
5. 자동승인된 미배정 세션을 실제로 #004 배정 화면에서 예정일 확정 → 추천 후보 계산(전문분야 일치 강사 1순위 정상 산출) → 임시배정까지 끝까지 진행해, 기존 배정 파이프라인과 완전히 호환됨을 확인.
6. 첫 시도에서 RLS 오류로 자동승인이 조용히 실패하는 걸 발견해 서비스 롤 처리로 수정 후 재검증(위 1~5가 수정 후 결과).

`next build` 타입 에러 없음, 콘솔·서버 에러 없음(HMR 관련 무해한 경고 제외). 검증용으로 만든 테스트 신청서·수업·배정 데이터는 전부 삭제해 원상복구했습니다.
