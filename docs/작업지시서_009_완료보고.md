## 4. 발견 / 판단

- **`matching_keyword` GENERATED 컬럼**: `COALESCE(NULLIF(btrim(sub_program),''), category, name)` — 세부 우선, 없으면 대분류. #004 매칭 로직은 `required_specialty` 를 그대로 쓰므로 승인 시점에 이 값을 세션에 스냅샷.
- **헤더/명세 분리**: 기존 `session_requests` 헤더 컬럼은 남겨두고(레거시 호환) 신규 흐름은 명세 사용. 마이그레이션이 기존 신청서를 명세 1건씩 이관.
- **`class_sessions` 구조 불변**: #004·#005·#007 은 `class_sessions` 를 읽으므로 영향 없음. 배정 화면의 "학교 희망일자"만 `session_requests` → `session_request_items` 로 연결 변경.
- **강사 정보 대리입력 좌우대조**: 범위대로 학교 신청 화면만 적용. 검증됐으니 동일 패턴을 강사 화면에 적용은 후속(필요 시 별도 작업지시서).
