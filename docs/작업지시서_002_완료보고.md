## 1. 구현 내용

### 공통 (인증/라우팅)
- **Supabase Auth**(`@supabase/ssr`) 이메일·비밀번호 로그인 (`/login`)
- `proxy.ts` (Next 16, 구 middleware)에서 매 요청 세션 갱신 + 미로그인 시 `/login` 리다이렉트
- 로그인 후 `app_accounts.role` 에 따라 자동 분기: staff → `/staff/requests`, school → `/school`, instructor → `/instructor`(준비중 안내)
- 모든 DB 접근은 로그인 사용자 세션으로 → **RLS 가 사용자 기준 적용**

### 학교 계정 (`school`)
| 화면 | 내용 |
| :--- | :--- |
| `/school` | 본인 학교 신청 목록 (상태 배지: 제출됨/검토중/승인/반려). 반려 건은 반려 사유 표시, 승인 건은 안내 문구 |
| `/school/new` | 신규 신청 폼 — 프로그램(드롭다운) / 희망일자(복수, 행 추가·삭제) / 희망 시간대 / 예상 인원 / 필요 전문분야 / 필요 강사 수(기본 1) |

- 제출 시 `request_status='submitted'`, `submitted_by` = 로그인 계정 `display_name` 자동 기록, `academic_year` = 현재 연도 자동
- **필수(프로그램·희망일자 1개 이상·필요 전문분야)** 미입력 시 제출 버튼 비활성 + 안내 메시지, 서버에서도 재검증

### 담당자 계정 (`staff`)
| 화면 | 내용 |
| :--- | :--- |
| `/staff/requests` | 전체 학교 신청 목록, 상태별 탭 필터(`?status=`), 표 형태 |
| `/staff/requests/[id]` | 신청 상세 + 검토 처리 패널 |

- **승인**: `approve_session_request(request_id, reviewer)` RPC 호출
  - `session_requests.request_status='approved'`, `reviewed_by`/`reviewed_at` 기록
  - **동시에** `class_sessions` 1건 생성 — `request_id` 연결, program/school/희망사항 복사, `scheduled_date` = 희망일자 첫 값(없으면 NULL), `session_status='unassigned'`
  - 한 트랜잭션에서 처리, 이미 처리된 건은 거부
- **반려**: `request_status='rejected'`, `rejection_reason` **필수**(빈 값 제출 불가), `reviewed_by`/`reviewed_at` 기록
- **검토중**: `submitted` → `reviewing` 전환 버튼 (선택적)

## 4. 발견/보완

(대시보드 Auth UI 나 admin API 로 만들면 발생 안 함)
